# 上游工作流完整稽核

這份稽核逐一研究兩個上游來源的工作流、模型與節點、輸入／輸出、授權、公開版本對應位置，以及尚未完成的整合。**目錄收錄、JSON 靜態檢查、原生編輯器載入、表單／執行器串接及實際 GPU 驗證，是不同階段。這兩批上游圖檔的實際 GPU 驗證數為 0。**

報告日期為 2026-11-10，公開程式碼比較基準是 [`95e2079ed3ae47f76ff67948f80673f410abd407`](https://github.com/TED-H-com/Web_Comfyui/tree/95e2079ed3ae47f76ff67948f80673f410abd407)。逐項報告保留這個歷史基準；下方另列稽核後完成的修正。後續程式碼新增功能，不會自動把舊圖檔升格為已通過執行驗證。

dseditor 共 213 筆稽核紀錄，包含 203 個可讀圖表示、4 個非工作流 JSON 與 6 個未解密成員；不能把 213 全部宣稱為可執行工作流。203 個可讀圖表示中有 166 個通過、37 個未通過基準版頂層檢查。根目錄與巢狀目錄的 Kontext rendering 圖完全相同，所以可讀圖表示有 202 組不同的原始位元組內容。

公開版本的 40 個 dseditor 副本來自 24 個精選匯入及 16 個基礎範例。其中 `sdxlhandfix.json` 有兩種清理後副本，因而只有 39 個不同上游路徑。工作流庫合併目錄與來源對照後有 140 個 dseditor 項目；這也不是 140 個可執行功能。ecjojo 的 94 個路徑對應 82 組不同的原始位元組內容，全部維持來源參考。

未通過連線檢查不等於 JSON 語法毀損。一般 JSON 均可解析；失敗包括過期連線、缺失節點、不互相對應的插槽或特殊前端路由。修復需要閱讀實際圖與節點規格，不能直接刪除連線或猜測模型。

## 已完成的程式修正

稽核後的修正限於匯入器、工作流庫與相關測試；沒有把尚未驗證的來源大量改成可執行項目。

- 匯入器保留被引用的現代子圖定義與介面綁定，移除未使用的定義及快取，並檢查子圖內部連線。依賴清單可展開子圖，避免只留下 UUID 包裝節點。
- 缺失或遞迴子圖會明確拒絕。匯入器也拒絕需要另外遷移的舊 `workflow/` 與 `workflow>` 群組，避免靜默移除其執行內容。工作流庫會拒絕未解析群組及不支援的 `workflow>` 格式。
- GPL-3.0 的 dseditor 來源參考若未被選為本機匯入，錯誤訊息會說明選擇政策；不再錯稱上游沒有再散布授權。ecjojo 沒有找到再散布授權，仍維持來源參考。
- NPNet Golden Noise 的權重路徑尚未核對時，依賴狀態保持「部分確認」。節點存在本身不會被當成模型已就緒。

驗證結果：133 個相關靜態／單元測試通過；重新清理 24 個精選來源後，全部仍符合既有固定輸出雜湊。實際上游 `LTXVideoSleepy0218.json` 的三個子圖均可保留並通過新增靜態檢查，展開後得到 32 種具體節點。公開工作流庫仍有 248 個總項目。這些結果都不代表圖檔已在 GPU 上生成成功。

測試使用 `pytest-disktmp` 建立並清除磁碟暫存目錄，沒有使用 tmpfs。報告內原始的 89 個及 45 個測試結果屬於各來源稽核時的基準證據；133 個是修正後的合併相關測試結果。

## 仍待完成的工作

- 11 個 dseditor 歷史目錄項目缺少啟用中的巢狀依賴。匯入器的展開能力已修正，但尚未批次重建所有來源參考清單，也未將它們轉為本機可執行圖檔。
- 三個 ecjojo 項目把停用／繞過分支中的節點列入儲存清單；「圖中存在」與「本次會使用」必須分開。19 個 ecjojo 圖還有檔名清單以外的模型或預設選項。
- 精選 NPNet 圖內的舊路徑已清理成占位文字，仍需設定有效權重。部分 SDXL checkpoint 是託管平台數字 ID，需要明確解析合法本機模型，不能猜測檔名。
- 自動下載節點、LoRA／底模相容性、注意力核心、量化格式、VRAM、遮罩、參考角色、音畫同步及輸出品質尚未逐圖實測。
- 「載入 ComfyUI」會把本機視覺 JSON 存入原生編輯器側欄，不會替任意上游圖建立表單、呼叫 `/prompt` 或建立 GPU 成功紀錄。現有肖像、H3、Qwen 功能採用相似方法，不構成這些特定圖檔的執行證明。
- YouTube 範例包含對外上傳／修改播放清單的程式碼；Krita、畫面擷取、Ollama、Gemini 等各有橋接或服務需求。不能把所有 JSON 都當成相同的影像生成工作。
- 六個 `SpecialUsage/workflowsummit.zip` 加密成員未取得密碼，內容明確標記為未檢視。檔名不能取代實際節點與模型分析。

接上本機或遠端供應商前，需逐項建立輸入角色、API 圖或原生橋接、相依版本、輸出綁定、取消／失敗處理與預算／任務身分規則，再進行另外授權的實際生成驗證。上游預覽圖、教學展示與靜態測試不會被轉寫成已完成的執行證據。
