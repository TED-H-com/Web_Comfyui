## 已修正與已顯示的問題

- 前端將 `extra`、`definitions`、`subgraphs` 或 `groupNodes` 儲存為 JSON `null` 時，公開讀取器現在接受空中繼資料；匯入器也能正常清理。錯誤型別例如 `false` 或空陣列仍拒絕。
- 相依檢查現在直接讀取圖形節點，避免呼叫者傳入過期、只含頂層節點的目錄資料而漏報缺少的巢狀節點。
- 233 個來源加入 `source_review`。只有來源 ID、SHA-256 與 commit 同時符合才套用；傳回固定的繁中警語與結構計數，不傳回上游提示詞、任意 widget 值或認證參數。
- 11 個 dseditor 項目的原始目錄遺漏啟用中的巢狀節點；28 個 dseditor 與 3 個 ecjojo 項目包含停用節點。純參考項目的詳情現在使用經雜湊綁定的啟用節點清單，保留原始目錄差異警語，不改變其可匯入狀態。
- 19 個 ecjojo 圖的隱含模型或預設選項，以及 22 個來源連線問題、11 個格式限制，都透過 API 警語顯示。上述類別互有重疊，總共 **68 個項目**帶警語。沒有警語的 165 個項目只標為 `reviewed-static`。

`source_review.scope` 為 `pinned-upstream-source`。它描述歷史稽核的固定上游位元組，不是目前已修改本機圖的執行認證。`import_format_supported` 僅表示圖形格式層面的能力；ecjojo 仍因未找到再散布授權而保持純參考，其他未選入的 GPL 圖也不會自動匯入。讀取器快取的是兩份公開稽核 JSON 的精簡結構資料，報告變更後由檔案狀態失效；部署時需一併放置這兩份報告。

## 私有部署與公開版的差異

比較僅讀取已知程式與公開來源目錄，並用上游公開圖作隔離測試。沒有列舉或讀取私有工作流內容、使用者上傳、媒體、帳戶、認證或私有執行驗證報告；也沒有對私有應用程式呼叫 `catalog()`。因此下列是程式快照與已知路徑存在性的比較，不是完整線上素材或 GPU 狀態盤點。

## 可重現測試

執行前將兩個環境變數設為相應固定版本的唯讀 checkout；測試逐檔校驗目錄 SHA-256，不執行上游程式。未設定來源路徑時，233 個來源測試會明確跳過；公開本機路由測試仍執行。

```bash
export COMMUNITY_DSEDITOR_SOURCE_DIR=/path/to/ComfyuiWorkflows
export COMMUNITY_ECJOJO_SOURCE_DIR=/path/to/ComfyUI-Templates
pytest-disktmp uv run --with pytest pytest -q \
  scripts/test_community_workflows.py \
  scripts/test_workflow_library.py \
  scripts/test_community_workflow_sources.py \
  scripts/test_workflow_guides.py \
  tests/test_workflow_library_unit.py \
  tests/test_workflow_guides_unit.py
```

本次結果：**631 passed**。測試資料使用磁碟暫存，沒有 `/dev/shm`。相依測試同時使用傳統與 V3 合成 COMBO schema，結果相同；空合成 inventory 會依實際啟用圖列出缺少節點。模型選項由公開來源建立，所以只證明解析與傳輸邏輯，不代表任何真實機器已安裝權重。

## H3 Colab 端到端重查

本輪仍使用固定的 H3 skill 與 google-colab-cli 0.7.4，沒有偷偷升級模型或來源版本。以下是實際找到並修正的問題：

| 缺口 | 修正與證據 |
|---|---|
| Jupyter 的 MIME Base64 換行遭當成損壞資料；部分檔案以文字回傳 | 明確要求 base64、接受標準換行、計入線上資料大小；以真實 Requests／固定 SDK 的 HTTP adapter 驗證 |
| 授權失效後，執行中任務無法重新登入回收 | Google userinfo 驗證並固定帳號身分；允許原帳號重新授權，拒絕換帳號覆蓋；同帳號的不同設定共用任務限制 |
| 舊 kernel 消失後每次輪詢又開一個 | 保存 SDK 重建後真正的 kernel／session ID；兩次執行只建立一次替代 kernel |
| OAuth 交換的重新導向限制放錯位置 | 限制實際 OAuth HTTP session，測試 307 不會轉送授權碼 |
| 缺少模組、設定損壞或執行器崩潰時一直等待 | 啟動失敗寫入 UUID／雜湊綁定的失敗狀態；控制器檢查程序身分與啟動期限；實際子程序語法錯誤測試確認立即回收 |
| 損壞輸入直到租 GPU 後才發現 | 付費申請前解碼所選圖片、檢查影音串流及 ffprobe；不掃描既有素材 |
| 永久無效或超限成果重試直到扣費期限 | 明確停止並回收；只有暫時傳輸問題會重試；成果種類須符合請求 |
| 取消未回應申請後，一次空查詢就宣告已釋放 | 保留申請身分與短暫確認期；遲到的同一個執行階段仍會被找到並釋放 |

瀏覽器測試不再全部替換 Colab API 回應：新增真實 WebUI → HTTP → SQLite → 子程序的建立帳號、登入、送出、取消與回收測試。只有 Google 傳輸子程序使用明示合成回應。另以實際安裝的固定 SDK 測試 HTTP 契約，沒有向 Google 傳送帳號或付費請求；CI 增加獨立 Colab SDK 測試工作。

本輪控制端測試 18 項、固定 SDK／橋接測試 49 項、遠端執行器測試 47 項均通過；這些數量有別於整體回歸測試，不應相加當成不重複的總數。工作庫警告在 390／768／1440 寬度以實際後端資料驗證；公開文件站也包含相同查核資訊。
